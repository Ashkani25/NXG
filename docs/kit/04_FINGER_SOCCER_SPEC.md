# Finger Soccer — طراحی کامل و نمونه‌ی مرجع (Flutter + Dart + Flame)

نمونه‌ی کامل در `samples/finger_soccer/` است و **الگوی مرجع تمام بازی‌های Arcade** (به‌خصوص بازی‌های فیزیکی Carrom و Billiards) محسوب می‌شود.

## ۱. ایده‌ی بازی
دو تیم، هرکدام ۵ مهره‌ی گرد (پاک)، یک توپ، زمین عمودی. نوبتی هستند: بازیکن یک مهره‌ی خودش را می‌کشد (فلاخن) و رها می‌کند؛ مهره‌ها و توپ با فیزیک برخورد می‌کنند؛ وقتی همه‌چیز ایستاد نوبت عوض می‌شود. توپ کامل از خط دروازه رد شود = گل. بازی تا ۵ گل یا ۴۰ نوبت. تیمی که گل خورده بازی را شروع می‌کند. تایمر نوبت ۱۵ ثانیه (در صورت تمام شدن نوبت می‌پرد).

## ۲. اصل معماری: سه لایه
1. **هسته‌ی خالص Dart** (`lib/finger_soccer/core/`): `config`, `body`, `physics`, `fs_match`, `bot`. هیچ import ای از Flame/Flutter ندارد. تست‌پذیر، قطعی (deterministic)، قابل اجرا روی سرور.
2. **رندر Flame** (`flame/finger_soccer_game.dart`): فقط (الف) گام ثابت `1/120s` را به simulator می‌دهد، (ب) می‌کشد، (پ) لمس را به `FsShot` تبدیل می‌کند.
3. **UI Flutter** (`ui/finger_soccer_page.dart`): HUD، ژست‌ها، دکمه‌ها.
قانون: منطق بازی هرگز داخل Flame یا ویجت نیست.

## ۳. قرارداد قطعی بودن (Determinism Contract)
- گام ثابت `dt = 1/120`، انتگرال‌گیری Euler نیمه‌ضمنی، ترتیب ثابت: حرکت ← تیرهای دروازه ← جفت‌ها (i<j) ← دیوارها.
- اعداد `double` استاندارد IEEE؛ فقط `+ - * /` و `sqrt`؛ بدون `sin/cos/pow` در فیزیک (تا تفاوت بین Dart و JS نیاید).
- مهره با سرعت زیر `6` متوقف می‌شود (صفر دقیق)؛ «ایستاده بودن» یعنی همه‌ی سرعت‌ها دقیقاً صفر.
- بعد از هر نوبت مکان‌ها به `1/1000` گرد می‌شوند (`floor(v*1000+0.5)/1000`) و سرعت‌ها صفر.
- `stateHash` (FNV-1a روی x,y گرد‌شده) برای تطبیق کلاینت و سرور.
- **منبع حقیقت (reference):** `supabase/functions/submit_shot/physics.ts`. نسخه‌ی Dart باید عملیات‌به‌عملیات همان باشد. تست `golden vector` در `test/finger_soccer_test.dart` این برابری را می‌سنجد.

### بازتولید golden vector بعد از تغییر پارامتر فیزیک

```bash
node --experimental-strip-types tools/golden.mjs   # مقادیر steps/hash را چاپ می‌کند
# سپس مقادیر را در test/finger_soccer_test.dart به‌روز کن و flutter test را اجرا کن
```
(`tools/golden.mjs` همین‌جا در بسته هست.)

## ۴. پارامترهای فیزیک (قابل تنظیم فقط با به‌روزکردن هر دو نسخه)
| پارامتر | مقدار | توضیح |
|---|---|---|
| زمین | 680×1000 | واحد منطقی |
| دروازه | عرض 220، عمق 46 | تیرک شعاع 6 |
| مهره | شعاع 34، جرم 1.0 | |
| توپ | شعاع 20، جرم 0.35 | |
| اصطکاک (drag) | 1.35 /s | |
| ضریب برگشت | مهره-مهره .90، توپ .96، دیوار .82 | |
| سرعت حداکثر شوت | 2300 u/s | power∈(0,1] |
| حداکثر زمان شبیه‌سازی | 9 s (1080 گام) | بعد از آن نوبت ختم می‌شود |

## ۵. ورودی
فلاخن: لمس نزدیک مهره‌ی خودی (≤1.9 شعاع) → کشیدن به عقب → جهت = مخالف کشش، قدرت = طول کشش / 170. پیش‌نمایش: خط نقطه‌چین جهت، کمان قدرت دور مهره، رنگ سبز→قرمز.

## ۶. بات (آفلاین)
`FsBot` ۸/۲۲/۴۸ شوت نامزد تولید می‌کند (هدف‌گیری توپ و نقطه‌ی پشت توپ به سمت دروازه + نویز زاویه)، هرکدام را با **همان شبیه‌سازی واقعی** روی نسخه‌ی clone اجرا و با تابع امتیاز (گل=±1e6، فاصله‌ی توپ تا دروازه) انتخاب می‌کند. سطح‌ها: easy/normal/hard.

## ۷. آنلاین (سرور-محور)
- جدول‌ها: `fs_matches`, `fs_shots` (فایل SQL در `supabase/migrations`). کلاینت فقط **می‌خواند**؛ نوشتن فقط توسط Edge Function با service role.
- جریان: کلاینت `submit_shot({matchId, shot})` می‌فرستد ← سرور اعتبارسنجی (نوبت، مهره‌ی خودی، قدرت، تایمر) ← شبیه‌سازی با `physics.ts` ← ذخیره state/hash/shot (کلید یکتا `(match_id, turn_number)` برای idempotency) ← Realtime به هر دو بازیکن.
- **پیش‌بینی کلاینت:** کلاینت همان لحظه با همان هسته شوت را شبیه‌سازی و نمایش می‌دهد؛ وقتی state سرور رسید، `stateHash` را مقایسه می‌کند؛ اگر نابرابر بود، state سرور را اعمال می‌کند (resync).
- ضد تقلب: سرور فقط `bodyId, dirX, dirY, power` را می‌پذیرد؛ نتیجه را خودش حساب می‌کند.
- تایمر: `turn_deadline` سمت سرور؛ پایان‌یافتن نوبت با cron/Edge Function یا هنگام درخواست بعدی تشخیص داده می‌شود.
- Reconnect: state کامل از `fs_matches.state` خوانده می‌شود.

## ۸. گرافیک
- زمین: `assets/games/finger_soccer/pitch.webp` (۱۰ راه سبز، خطوط، دروازه‌ی تور‌دار با قاب فیروزه‌ای NEXORA). اگر نبود، رسم پروسیجرال fallback.
- مهره‌ها: `pucks/top/<skin>_top.webp` با حلقه‌ی تیمی (فیروزه/صورتی)؛ سایه‌ی نرم؛ حلقه‌ی روشن برای مهره‌های تیمِ نوبت‌دار.
- توپ: `ball.webp`؛ دنباله (trail) محو‌شونده در Medium/High.
- کیفیت: `FsQuality.low` سایه و trail را حذف می‌کند؛ `high` همه را فعال دارد. (به `GraphicsQualityService` در STEP_05 وصل شود.)
- برای ارتقا: ذرات برخورد، فلش گل، لرزش دوربین، صدای برخورد (حداقل ۳ لایه‌ی صدا: برخورد مهره، برخورد دیوار، گل).

## ۹. اتصال به NEXORA
- یک `GameModule` با id `finger_soccer` بساز که `createGame()` → `FingerSoccerGame`، `rulesEngine` → `FsMatch`، `assets` → فهرست پاک‌ها را برگرداند (قرارداد STEP_16).
- XP: رویدادهای `game.finger_soccer.goal`، `.win`, `.match_played` از طریق `award_xp` (STEP_13) — **فقط سمت سرور** بعد از `status = finished`.
- پوسته‌ها (skin) پاک‌ها از `inventory` (STEP_28) خوانده شود؛ پیش‌فرض‌های رایگان: `nx_green` و `tech_nx`.
- پدستال Arcade: `assets/arcade/pedestals/finger_soccer.webp`.

## ۱۰. اجرای نمونه
```bash
cd samples/finger_soccer
flutter create . --platforms=android      # فقط یک‌بار؛ پوشه‌ی android را می‌سازد
flutter pub get
flutter analyze && flutter test
flutter run                                # یا از GitHub Actions APK بساز
```
> توجه: کد نمونه در محیط تولید این بسته **کامپایل نشده** (Flutter آنجا نصب نبود). منطق فیزیک نسخه‌ی TypeScript آن با Node اجرا و تست شد؛ ایجنت باید اولین کاری که می‌کند `flutter analyze` و `flutter test` باشد و هر خطای کامپایل را رفع کند (احتمالاً جزئی).
